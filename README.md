# 19🥕b судейство — V108

Домен сайта: https://tuz19.ru/ — подключён владельцем в Pages; на момент передачи DNS ещё не распространился, HTTPS нужно проверить после его настройки.

Стандартный адрес Pages: https://8myy4p2fgm-ux.github.io/ib19/ — перенаправляет на пользовательский домен.

Репозиторий: https://github.com/8myy4p2fgm-ux/ib19

Публичный статический проект на основе единственного эталона `IB19_REDESIGN_V108_COMPACT_JUDGES.html`. Vanilla JS, CSS, JSON; React, база данных и постоянный сервер не нужны. Оригинал сохранён в `docs/V108.html`.

## Что где находится

- `index.html`, `css/styles.css` — исходная разметка и все стили V108 в прежнем порядке.
- `js/app.js` и модули — исходная логика V108, выделенная из HTML. Дополнительные обработчики находятся в `interactions-*.js`.
- `data/19ib_all_judges_REPAIRED.json` — основные оценки, комментарии и source timestamp.
- `data/forum.csv` — отдельный авторский справочник UUID, имён и групп OG/Ветераны. Сборщик читает его при каждом обновлении. Общий список API никогда не заменяет этот справочник.
- `data/forum_judges_export.json` — собранные оценки и сохранённые ручные поля авторских записей. Членство, имена и группы берутся из CSV, оценки — из API по UUID; похожие ники никогда не сопоставляются.
- `data/metadata.json` — время последнего успешного сбора, ID раунда, контрольные количества.
- `data/history.json` — исходный снимок, изменения оценок/комментариев с before/after и observedAt, наблюдавшиеся значения индексов двух групп.
- `scripts/` — сбор, проверка, история и копирование статических файлов в `dist/`.

## Запуск на компьютере

Установите Node.js 22 или новее. В папке проекта:

```sh
npm ci
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173). Открытие `index.html` двойным кликом больше не заменяет веб-сервер: модульный сайт получает внешние JSON. Постоянный сервер нужен только для локальной разработки, GitHub Pages раздаёт готовые файлы.

## Обновить вручную

```sh
npm run update
npm run validate
npm test
npm run build
```

Источники проверены по публичному коду самого 19ib.ru: `/rounds/{id}/full`, `/rounds/{id}/entries/{userId}/scores`, `/rounds/{id}/live` на `https://api.19ib.ru`. ID закреплён в `scripts/source-config.json`, случайный следующий раунд не выбирается.

Два одновременных запроса, не чаще двух начал запросов в секунду; timeout 20 секунд, максимум две повторные попытки. Все оценённые участники перечитываются, включая завершённых, чтобы замечать исправленные комментарии. После длинного чтения сборщик сверяется с live и перечитывает изменившиеся записи. Полный сбор может занимать 15–30 минут. Ошибка приводит к ненулевому exit code; GitHub не коммитит и не публикует неудачный сбор.

В публичном API сейчас отсутствуют три прежних участника. Их записи сохраняются в `archivedMembers` с `current:false`, `sourceAbsentSince`; баллы и авторские связи не удаляются. В текущем `members` находятся только участники API; архив не увеличивает число участников, максимум оценок и статистику. Это не автоматически выдуманный статус выбывания. ID отсутствующих записаны в метаданных успешного сбора. При возвращении UUID он автоматически снова включается в текущий состав. Если список внезапно уменьшится более чем на 10% или правила раунда изменятся, сбор остановится для ручной проверки.

## GitHub и Pages

Репозиторий: https://github.com/8myy4p2fgm-ux/ib19

1. Загрузите/синхронизируйте эти файлы в ветку `main`.
2. В GitHub откройте **Settings → Pages → Source → GitHub Actions**.
3. На вкладке Actions разрешите workflows, если GitHub предлагает включить их.
4. В Settings → Actions → General разрешите workflow доступ на запись contents. Не выдавайте доступ к другим репозиториям.
5. Запустите **Deploy Pages → Run workflow**. Адрес должен быть `https://8myy4p2fgm-ux.github.io/ib19/`.
6. Запустите **Update judging data → Run workflow** для первого актуального сбора.

Workflow обновления запускается на 17-й минуте каждого часа, есть ручной запуск. GitHub может задерживать задания; расписание не является гарантией точного часа. Один сбор не пересекается с другим. У workflow нет пользовательского токена или секретов: публичный API и стандартный GITHUB_TOKEN.

Важно: push, сделанный GITHUB_TOKEN, не запускает другой workflow. Поэтому обновление само публикует Pages после успешного коммита данных. Обычный push main запускает отдельный deploy. Новые JSON публикуются вместе со статическими файлами, без пересборки JavaScript. Переключите Pages на GitHub Actions, а не на устаревшее «Deploy from a branch».

В логе сбора каждые 100 ответов появляется прогресс; в конце — число участников/оценок/судей и время observedAt. Оба workflow используют общую очередь публикации.

## История и ограничения

`scoredAt` — время выставления оценки из API. `observedAt` — когда успешный сбор обнаружил новую запись или изменение. Первое обнаружение старых оценок неизвестно: исходный снимок не выдаётся за журнал событий прошлого. История исправлений начинается с работы нашего сборщика. Графики V108 продолжают свой согласованный пересчёт из актуальных scoredAt; сохранённые наблюдавшиеся индексы и before/after позволяют отдельное точное воспроизведение состояния после начала мониторинга.

История не очищается при отсутствии новых оценок. Дубликат перехода в том же observedAt не записывается повторно; новый обратный переход считается отдельным исправлением. При достижении 20 MiB история не удаляется: обновление останавливается. Для архивирования сохраните старый файл под датированным именем в data/history/, оставьте ссылку в документации, затем начните новый baseline из текущих записей через reviewed migration. Нельзя просто удалить журнал.

## Восстановить предыдущие данные

В GitHub найдите последний успешный коммит перед ошибкой, восстановите **весь набор** `data/` (основной JSON, форумный JSON, metadata и history), сделайте новый коммит и запустите Deploy Pages. Не восстанавливайте один JSON отдельно. Через Git можно использовать `git restore --source=<commit> data` и затем `git commit`/`git push`.

## Поддержка

Меняйте CSS в css/styles.css, логику — в соответствующем модуле js/, авторский состав — в data/forum.csv по точным userId. Дополнительные ручные поля остаются в forum_judges_export.json и не затираются при обновлении. После изменения CSV запустите Update judging data. После изменения кода выполните тесты и сравните скриншоты. Исходные формулы не заменяйте из прежних прототипов.

При изменении состава история сохраняет selectionVersions и selectionChanges отдельно от изменений оценок. Динамику, пересчитанную на новом составе, нельзя трактовать как изменение отношения судей только из-за смены выборки. Подробности актуализации: docs/ROSTER_UPDATE.md.

Для собственного домена: в Settings → Pages задайте Custom domain, добавьте DNS-записи по инструкции GitHub и включите Enforce HTTPS. Пути файлов относительные, домен и подпапка не зашиты в frontend.
