АРХИТЕКТУРА
Карточка использует основную модель D.byId/D.archivedById и локальный индекс
по подтверждённым UUID. Код, CSS и агрегация профилей загружаются только при
переходе в раздел «Судьи», не при первой загрузке «Обзора».
Прямой URL: /judges/?judge=UUID. Поиск, балл, порядок и страница — в query.
Таблицы судей и их обработчики не переписаны: имена получают обычные ссылки.
Длинные комментарии раскрываются; на мобильном доступны все поля.

ДАННЫЕ
В основную выгрузку добавлены judges (userId/name/avatarUrl/bio) и
judgeIdentities (подтверждённые соответствия имён UUID), а участникам — trackId.
Отдельный JSON/планировщик не нужен: существующий workflow продолжает
публиковать свои четыре файла. Схемы GitHub Actions и Cloudflare не менялись.

Сборщик при включённом judgeProfiles добавляет один GET /judges к текущему
циклу. При ошибке/повреждённом ответе сохраняет последний справочник;
сбор оценок продолжается по старому механизму. Каталог хранит прежние UUID
для истории. trackId берётся из /full и не стирается пустым значением.
Повторный сбор оценок для начального заполнения не выполнялся:
только GET /judges и GET /rounds/{id}/full, без /entries/*/scores.

Оценка в API содержит только judgeName. Соответствие UUID берётся из точного,
однозначного публичного каталога. При переименовании сохраняется ранее
наблюдавшееся соответствие имени тому же UUID; нечётких или придуманных
алиасов нет. При коллизии разных UUID с одним именем оценки не приписываются
одному из них наугад; исходные строки сохраняются. Для гарантированной
идентичности при таких коллизиях нужен judgeId непосредственно в API оценок.

Оценки, комментарии и даты исходного main сохранены структурно без изменений,
включая архив. Справочник и trackId не входят в записи журнала оценок,
поэтому их добавление не создаёт фиктивные правки в history.json.
Сам history.json и форумные сопоставления не изменены.
Профиль считает все актуальные сохранённые оценки, в том числе архивные;
исправления не удваиваются. Числа из V3 не зашиты в реализацию.
runId обновлён с суффиксом версии, чтобы прежний JSON не брался из кеша.
exportedAt/lastSuccessfulAt и время оценок при обогащении не подменялись.

ОГРАНИЧЕНИЯ
Нет гарантии доступности внешнего изображения/аудио; при ошибке фото —
согласованная заглушка, а ссылка на карточку артиста присутствует всегда.
Неизвестные имена архивных участников не выдумываются.
Профили используют тот же фиксированный в памяти снимок, что и весь сайт;
новые данные видны после штатной перезагрузки страницы.
